# Process Management

여러 서버에 SSH 로 접속해 등록한 프로세스가 실행 중인지 확인하고, 로그를 보고, 시작 · 중지 · 재시작하는 관리 화면입니다.
꺼진 프로세스를 자동으로 다시 시작할 수도 있습니다.
서버는 직접 만든 그룹(의왕, 광명 ...)으로 묶어서 보여줍니다.

## 사용 방법

- **그룹 이동**: `/all` 은 전체 화면으로, 상단에 모든 그룹 탭이 보입니다. `/uw` 처럼 그룹 slug 주소로 들어오면 그 그룹만 보이고, 상단에도 그 그룹 탭만 보입니다. (그룹마다 주소를 나눠 줄 때 쓰세요)
- **상태 확인**: 몇 초마다 각 서버에서 `ps` 를 실행해 프로세스별 PID · CPU · MEM · 실행 시간을 보여줍니다. 초록은 모두 실행 중, 주황은 일부 중지, 빨강은 모두 중지되었거나 SSH 접속에 실패한 서버입니다. 왼쪽 사이드바에서 서버를 누르면 해당 카드로 이동합니다.
- **로그**: `로그` 를 누르면 로그 파일 목록(최근 수정 순)이 나옵니다. 따로 정하지 않았으면 시작 스크립트 폴더 아래 5단계까지의 `*.log` 입니다. 파일을 누르면 마지막 줄들을 봅니다. 줄 수를 바꾸거나, 단어로 거르거나, 3초 자동 새로고침을 켤 수 있습니다. **⤓ 화면 내용**은 지금 보이는 줄만(예: 마지막 200줄, 거르기를 했으면 걸러진 줄) 파일로 받고, **⤓ 전체 파일**은 로그 파일 전체를 받습니다. `Esc` 는 파일 화면에서 목록으로, 목록에서 창 닫기입니다.
- **INI**: `INI` 를 누르면 INI 파일 목록이 나옵니다. 따로 정하지 않았으면 시작 스크립트 폴더 아래 3단계까지의 `*.ini` 입니다. 파일을 누르면 편집기가 열리고, **저장**(`Ctrl/⌘ + S`)하면 서버의 파일이 바뀝니다. 이전 내용은 같은 폴더의 `<파일>.bak` 에 남습니다. 연 뒤 다른 곳에서 파일이 바뀌었으면 저장하지 않으니 **다시 읽기** 후 고치세요. UTF-8 이 아닌 파일(EUC-KR 등)은 열 수 없습니다.
- **자동 재시작**: 각 프로세스의 `감시` 버튼(또는 이름 아래 `↻` 표시)에서 자동 재시작을 켜고 감시 문자열 · 감시 이름을 정합니다. **지금 맞는 프로세스 확인**으로 저장 전에 어떤 프로세스가 잡히는지 볼 수 있습니다. 자동 재시작을 켠 프로세스는 이름 아래에 `↻ 자동 재시작` 이 보입니다. 감시 프로세스가 없으면 Go 서버가 확인 주기(기본 10초) 안에 시작 스크립트를 실행하고, 재시작 대기(기본 30초) 뒤에도 없으면 다시 실행합니다. 두 시간은 `⚙ 설정` 맨 위에서 바꿉니다. 화면에서 **중지**하면 다시 시작할 때까지 자동 재시작이 멈춥니다(`자동 재시작 멈춤`). 표시에 마우스를 올리면 재시작 횟수 · 마지막 시각 · 오류가 보입니다.
- **시작 · 중지 · 재시작**: 중지는 찾은 PID 에 SIGTERM 을 보내고 종료될 때까지 최대 10초 기다립니다. 시작은 등록한 시작 스크립트를 실행합니다. 재시작은 중지 후 시작입니다.
- **검색**: 서버 이름 · 호스트 · 프로세스 이름으로 카드를 거릅니다.
- **설정**: `⚙ 설정` 에서 그룹 · 서버 · 프로세스를 추가 · 수정 · 삭제하고 저장하면 바로 반영됩니다. **내보내기**로 설정 파일을 받고(비밀번호 제외), **가져오기**로 다시 불러올 수 있습니다. 그룹 주소(`/uw`)에서 열면 그 그룹의 서버 · 프로세스만 편집하고, 그룹 · 확인 주기 · 가져오기/내보내기는 `/all` 에서만 바꿉니다. 설정 창을 연 뒤 `감시` 창이나 다른 사용자가 설정을 바꿨으면 저장되지 않으니(덮어쓰지 않도록), 창을 닫고 다시 열어 고치세요.

## 설정 항목

| 구분 | 항목 | 설명 |
|---|---|---|
| 그룹 | slug · 이름 | slug 는 주소(`/uw`)로 쓰는 영문 소문자 · 숫자 · `-`. `all`, `api`, `config`, `static` 은 쓸 수 없습니다 |
| 서버 | host · port · user · 비밀번호 | SSH 접속 정보 (port 기본 22). 비밀번호는 서버 파일에만 저장되고 화면에는 다시 보이지 않습니다 |
| 프로세스 | match | `ps` 명령줄에 대한 정규식. 다른 프로세스와 겹치지 않게 구체적으로 적습니다 (예: `java .*shelter\.jar`) |
| 프로세스 | 시작 스크립트 | 셸 특수문자가 없는 절대 경로. 인자 없이, 스크립트가 있는 폴더에서 실행합니다. 이 폴더가 로그 · INI 파일을 찾는 기준입니다 |
| 프로세스 | 로그 파일 · INI 파일 (선택) | 비우면 시작 스크립트 폴더 아래 5단계까지의 `*.log`, 3단계까지의 `*.ini`. 다른 곳을 보려면 패턴을 적습니다: 상대 경로(`logs/*.log`)는 시작 스크립트 폴더 기준, 절대 경로(`/var/log/shelter/*.log`)는 그대로 (여러 개는 쉼표). `* ?` 는 폴더(`/`)를 넘지 않고, 앞의 두 폴더는 와일드카드 없이 적어야 합니다 (`/home/*` 는 안 됨) |
| 프로세스 (`감시` 버튼) | 자동 재시작 · 감시 이름 · 감시 문자열 | 설정 창이 아니라 모니터링 화면에서 바꿉니다. 감시 이름은 실행 파일 이름(정확히 일치, 예: `java`), 감시 문자열은 명령줄에 들어 있어야 하는 글자(예: `/opt/shelter/shelter.jar`). 둘 중 하나만 적어도 되고, 둘 다 적으면 한 프로세스가 둘 다 만족해야 합니다. 이 프로세스가 없으면 시작 스크립트를 실행합니다 |

> 이 화면에는 로그인이 없습니다. 접속할 수 있는 사람은 누구나 프로세스를 중지 · 시작하고 설정을 바꿀 수 있으므로, 내부망에서만 열어 두세요.
